⚡ Optimize Wikilink Resolution Performance

**What:**
Optimized the way `renderMarkdown` resolves internal wikilinks against the list of `existingPages`. Previously, this operation required an $O(N)$ linear scan of all existing pages for *each* wikilink. We now build two lookup maps (`exactMatchMap` and `suffixMatchMap`) so that resolutions are $O(1)$.

**Why:**
To improve the performance of rendering markdown, especially when the workspace contains a large number of pages and the markdown document contains many links. The maps are built lazily upon encountering the first wikilink, so documents without links incur zero overhead.

**Measured Improvement:**
In a benchmark with 10,000 existing pages and 3,000 links being resolved:
- **Baseline (Old method):** ~2920 ms
- **New method:** ~25 ms (Map building ~24 ms + Resolution ~1 ms)
- **Improvement:** ~116x faster for this workload.
