🎯 **What:** Adds missing fallback error handling test suite for `setSetting` in `js/db.js` where `localStorage` was supposed to be a fallback if `indexedDB` fails. During implementation, it was discovered that `db.js` was missing an `await` before its returned `Promise` in the settings access methods, which caused asynchronous rejection errors from `indexedDB` (such as `put` operation failures) to bubble out past the try-catch block unhandled, defeating the fallback.
📊 **Coverage:** This PR adds `tests/unit/db.spec.js` running in Playwright that intercepts and mocks `IDBObjectStore.prototype.put` and `indexedDB.open` inside the browser evaluation space. It mocks both synchronous setup and async operational failure responses (by emitting to `onerror`) to simulate IndexedDB failures. The tests then assert that `localStorage.setItem` handles the failure and accurately saves the fallback data. The bug itself is also solved.
✨ **Result:** Test coverage improved handling `setSetting` database failures. Rejection handling has been properly fixed in the database wrapper enabling reliable localStorage fallback functionality across the `WikiFlowDB` persistence layer. Test suite runs green cleanly.
